Investigation, Mail, and Workflow Trace

Incorrect LDAP data in the timeline

  1. dashboard/app/investigation/page.tsx: requests page data.
  2. components/InvestigationTimeline.tsx: renders name, team, manager, and LDAP marker.
  3. InvestigationController.cs and WeeklyFlagService.cs: follow the timeline user-grouping source.
  4. DirectorySettingsService.cs: LDAP connection, attribute selection, and user lookup.
  5. TurkishNameHelper.cs: full-name and formal-address formatting.
  6. Shared/Models/Incident.cs: legacy FullName, Team, and LoginName fields persisted on incidents.

Incorrect mail-template field

  1. MailTemplateManager.tsx or SendMailModal.tsx: template and selected incident.
  2. Helpers/PlaybookMailRenderer.cs: expansion of {{tam_ad}}, {{destination}}, {{olay_tarihi}}, and {{max_match}}.
  3. DirectorySettingsService.cs: authoritative LDAP name, email, team, and gender data.
  4. InvestigationMailAutomationService.cs and PlaybookEngine.cs: automated or workflow-originated mail.

Incorrect query status or reply handling

  1. app/investigation/queries/page.tsx: query and workflow-mail tables.
  2. InvestigationQueriesController.cs: CRUD, reply-review, and inbox-scan endpoints.
  3. InvestigationQueryRecord.cs: persistent status values such as queried, reply pending review, and completed.
  4. InvestigationMailAutomationService.cs: sent-mail/reply matching, reminders, and catalog requests.
  5. InvestigationMailAutomationBackgroundService.cs: periodic IMAP scan loop.

Empty workflow report or pending mail

  1. app/investigation/agentic-workflows/[id]/page.tsx: node configuration, run, and report UI.
  2. NodePalette.tsx, NodeInspector.tsx, PlaybookCanvas.tsx: node type, parameters, and connections.
  3. PlaybooksController.cs: graph save, validation, run, and approval.
  4. PlaybookGraph.cs: node/graph JSON contract.
  5. PlaybookEngine.cs: metrics, ordering, report rows, and mail queue.
  6. PlaybookSchedulerService.cs, CronSchedule.cs, RadarTimeZone.cs: scheduling and Turkey time zone.

Service mailbox does not process mail

  1. InvestigationMailAutomationBackgroundService.cs: scan interval and logs.
  2. InvestigationMailAutomationService.cs: sender validation, catalog replies, reminders, and report-keyword parsing.
  3. DirectorySettingsService.cs: IMAP access and MIME parsing.
  4. PlaybookGraph.cs: workflow report_request_keywords.
  5. PlaybookEngine.cs and EmailService.cs: report generation and SMTP delivery.

Safe Working Rules

  1. Before deleting a class, find every reference with rg -n "ClassName".
  2. A new service needs a registration in ServiceCollectionExtensions.cs.
  3. When changing an API, update the frontend call and TypeScript type together.
  4. When changing mail or scheduling, test the background service and run/mail-log records.
  5. For a new persistent field, update the model, AnalyzerDbContext, migration/schema, controller, and frontend as one chain.
  6. Make cleanup changes small, separate, and verifiable commits.
Do not edit manually: **/bin/, **/obj/, dashboard/node_modules/, dashboard/.next/, log/build output, Office ~$*.xlsx temporary files, and environment/secret files are not source code.

Update this atlas in the same commit whenever a route, endpoint, service, integration, or background job is added.
